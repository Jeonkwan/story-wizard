## Actionable Review Checklist

- [x] **1. [CRITICAL] Infinite Polling Loop in `DirectorStudio.tsx` (`client/components/DirectorStudio.tsx` `useEffect` around `loadRecentJobs`):**
  - **Issue:** The `useEffect` calling `loadRecentJobs()` and registering the 2,000ms `setInterval` has `[loadRecentJobs, recentJobs]` in its dependency array. Because `loadRecentJobs()` calls `setRecentJobs(jobs)` (creating a new array reference on every response), React tears down and re-runs the `useEffect` immediately on every fetch, creating an infinite tight polling loop of `GET /api/admin/jobs` without waiting 2,000ms.
  - **Fix:** Split mount/`visibilitychange` handling (`useEffect(..., [loadRecentJobs])`) from the interval polling effect, and derive a primitive boolean `const hasRunningJobs = recentJobs.some((j) => j.status === 'running')` so the interval effect depends on `[loadRecentJobs, hasRunningJobs]` instead of the `recentJobs` array reference. Add a regression test in `tests/ui.test.tsx` verifying `fetchRecentJobs` is not called repeatedly in an immediate tight loop after mount.

- [x] **2. [HIGH] Async Closure Hijack When Queueing Another Story or Switching Stories (`client/components/DirectorStudio.tsx` `handleWriteStory` & `handleAutoDirect`):**
  - **Issue:** In `handleWriteStory`, `await writeStoryDraft(..., { async: true })` continues polling Job 1 until completion. If the user clicks `➕ Queue Another Story` (`handleQueueAnother`) or navigates to edit another story while Job 1 is running, and submits Job 2 (or edits another story), Job 1's resolving promise still executes `loadStoryIntoWorkbench(created.id)` and `finally { setIsWriting(false) }`, yanking the user away from their current screen and resetting Job 2's foreground loading state prematurely. Similarly, `handleAutoDirect` updates `activeStory` / `editedTurns` / `isDirecting` without checking if the user has since switched to another story.
  - **Fix:** Track a monotonic `draftSubmissionIdRef` (incremented on `handleWriteStory`, `handleQueueAnother`, `handleStartNewStory`, `handleStartSequel`, and `loadStoryIntoWorkbench`) and a `selectedStoryIdRef` (synced to `selectedStoryId`). In `handleWriteStory`, pass an `AbortSignal` (or foreground cancellation check) / verify `draftSubmissionIdRef.current === mySubmissionId` before mutating Step 1 state or calling `loadStoryIntoWorkbench` (letting the Generation Activity tray handle background completion notifications). In `handleAutoDirect`, verify `selectedStoryIdRef.current === targetStoryId` before mutating workbench fields. Add a regression test in `tests/ui.test.tsx` verifying that clicking `➕ Queue Another Story` and submitting a second draft prevents Job 1's completion from hijacking Job 2 or resetting `isWriting`.

- [x] **3. [HIGH] Duplicated Elapsed Seconds `(14s) (14s)` in Generation Activity Tray (`client/components/DirectorStudio.tsx` & `tests/e2e/qa-phase15.spec.ts`):**
  - **Issue:** Visual inspection of `qa-screenshots/phase15-activity-tray-running-dark.png` and `qa-screenshots/phase15-mobile-activity-tray-dark.png` revealed `"Drafting story with Gemini 3.8 Flash... (14s) (14s)"` and `"(8s) (8s)"`. `DirectorStudio.tsx` unconditionally appends ` (${job.elapsed_seconds}s)` to `job.message`, while `qa-phase15.spec.ts` (lines 41 and 202) included `(14s)` / `(8s)` inside `job.message`.
  - **Fix:** Remove the hardcoded `(14s)` / `(8s)` suffix from `job.message` in `tests/e2e/qa-phase15.spec.ts` (matching real backend messages in `server/routes/adminStories.ts`), AND in `DirectorStudio.tsx` avoid appending `(${job.elapsed_seconds}s)` if `job.message` already ends with `(\d+s)`. Re-run Playwright to refresh `qa-screenshots/phase15-*.png`.

- [x] **4. [HIGH] `direct` and `synthesize` Jobs Missing from `jobs.json` on Start & Non-Atomic Catalog Clear (`server/services/jobManager.ts`):**
  - **Issue:** `POST /api/admin/stories/:id/direct` and `POST /api/admin/stories/:id/synthesize` call `jobManager.createJob(..., false, ...)` (`autoPersist = false`) followed by `await jobManager.persistJobStart(job.job_id)`. Because `persistJobStart` only calls `persistStoryActiveJob` and does not call `this.saveJobToHistory(job)`, a `direct` or `synthesize` job is absent from `jobs.json` until it finishes—meaning a server restart mid-synthesis fails to record an `"Interrupted by server restart"` entry in `jobs.json`. Additionally, `reconcileStaleJobs()` clears `catalog.json` via `getCatalog()` + `saveCatalog()` instead of `updateJsonAtomic()`.
  - **Fix:** Call `await this.saveJobToHistory(job)` inside `persistJobStart(jobId)`, and update `reconcileStaleJobs()` to clear stale `active_job` entries in `catalog.json` via `this.storage.updateJsonAtomic(...)`. Add a regression test in `tests/jobManager.test.ts` verifying `createJob('synthesize', ..., false)` + `persistJobStart()` persists the running job in `jobs.json` and `reconcileStaleJobs()` transitions it to `failed` on restart.
